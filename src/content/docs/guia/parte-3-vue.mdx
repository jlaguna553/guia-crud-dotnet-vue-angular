## 3.1 Conceptos básicos de Vue

Un componente Vue de "Single File Component" (`.vue`) tiene tres bloques:

```vue title="Ejemplo.vue"
<script setup lang="ts">
// lógica: variables reactivas, funciones, props, emits
import { ref } from 'vue';
const contador = ref(0); // "ref" crea una variable reactiva
</script>

<template>
  <!-- lo que se ve, con enlaces a la lógica de arriba -->
  <button @click="contador++">{{ contador }}</button>
</template>

<style scoped>
/* CSS que solo aplica a este componente */
</style>
```

:::note[💡 Concepto: reactividad con `ref`]
`ref(valorInicial)` envuelve un valor en un objeto reactivo: cuando cambias `miRef.value`, Vue
automáticamente vuelve a renderizar cualquier parte de la plantilla que use esa variable. En la
plantilla no escribes `.value` — Vue lo "desenvuelve" automáticamente ahí. Es la base de todo
el framework: en vez de tú actualizar el DOM a mano, describes qué depende de qué, y Vue se
encarga del resto.
:::

## 3.3 Los tipos: Pedido y Cliente

Antes de escribir cualquier componente, define la forma de tus datos en TypeScript. Esto te da
autocompletado y errores en tiempo de compilación si te equivocas de nombre de campo — muy
valioso cuando el objeto tiene anidación.

```ts title="src/types/pedido.ts"
export interface Cliente {
  nombre: string;
  email: string;
}

export interface Pedido {
  id?: number | null;
  fecha: string;
  total: number;
  cliente: Cliente;
}
```

Nota que `id` es opcional (`?`) y puede ser `null`: un pedido nuevo, antes de guardarse,
todavía no tiene id — lo asigna el backend.

## 3.4 El servicio HTTP

Aísla todas las llamadas a la API en un solo archivo. Así, si el día de mañana cambias de
`axios` a `fetch`, o cambia la URL, solo tocas un lugar.

```ts title="src/services/pedidoService.ts"
import axios from 'axios';
import type { Pedido } from '../types/pedido';

const API_URL = 'http://localhost:5000/api/pedidos';

export const pedidoService = {
  async obtenerTodos(): Promise<Pedido[]> {
    const res = await axios.get<Pedido[]>(API_URL);
    return res.data;
  },
  async crear(pedido: Omit<Pedido, 'id'>): Promise<Pedido> {
    const res = await axios.post<Pedido>(API_URL, pedido);
    return res.data;
  },
  async actualizar(id: number, pedido: Pedido): Promise<void> {
    await axios.put(`${API_URL}/${id}`, pedido);
  },
  async eliminar(id: number): Promise<void> {
    await axios.delete(`${API_URL}/${id}`);
  }
};
```

:::

## 3.5 Componente de formulario: PedidoForm.vue

Este componente hace dos trabajos: crear un pedido nuevo, y editar uno existente — con el mismo
formulario. La clave para lograrlo es un **prop** opcional (`pedidoAEditar`): si viene `null`,
el formulario está vacío ("modo crear"); si trae un pedido, lo precarga ("modo editar").

```vue title="src/components/PedidoForm.vue"
<script setup lang="ts">
import { ref, watch } from 'vue';
import type { Pedido } from '../types/pedido';

const props = defineProps<{ pedidoAEditar?: Pedido | null }>();
const emit = defineEmits<{
  (e: 'guardar', pedido: Pedido): void;
  (e: 'cancelar'): void;
}>();

const formulario = ref<Pedido>({
  id: null, fecha: obtenerFechaActualIso(), total: 0.0,
  cliente: { nombre: '', email: '' }
});

const submit = () => {
  emit('guardar', { ...formulario.value });
};

// watch: cuando el padre cambia pedidoAEditar (click en "Editar"),
// rellenamos el formulario con esos datos
watch(() => props.pedidoAEditar, (nuevoVal) => {
  if (nuevoVal) {
    formulario.value = { ...nuevoVal, cliente: { ...nuevoVal.cliente } };
  } else {
    // limpiar formulario
  }
}, { immediate: true });
</script>

<template>
  <form @submit.prevent="submit">
    <input v-model="formulario.cliente.nombre" required />
    <input v-model="formulario.cliente.email" type="email" required />
    <input v-model="formulario.fecha" type="datetime-local" required />
    <input v-model.number="formulario.total" type="number" step="0.01" required />
    <button type="submit">{{ formulario.id ? 'Actualizar' : 'Guardar' }}</button>
  </form>
</template>
```

:::note[💡 Concepto: `v-model` en un campo anidado]
`v-model="formulario.cliente.nombre"` enlaza el input directamente a un campo *dentro* del
objeto anidado `cliente`. No necesitas ningún código extra para "sincronizar" ese campo — Vue
lee y escribe directamente esa ruta del objeto. Y `v-model.number` en el campo de total le dice
a Vue que convierta el texto del input a `number` automáticamente (si no,
`formulario.total` sería el string `"150.50"` en vez del número `150.50`).
:::

:::note[💡 Concepto: props y emits]
Un componente hijo **recibe** datos del padre por *props* (`defineProps`) y **avisa** al padre
de cosas que pasaron con *eventos* (`defineEmits` + `emit(...)`). El hijo nunca modifica
directamente el estado del padre — solo emite "oye, pasó esto" y el padre decide qué hacer.
Este flujo de datos en una sola dirección (props hacia abajo, eventos hacia arriba) es uno de
los principios más importantes al construir UIs con componentes, sin importar el framework.
:::

## 3.6 Componente de tabla: PedidoTabla.vue

Recibe la lista de pedidos y dos flags de estado (cargando, vacío), y emite eventos cuando el
usuario pide editar o eliminar una fila.

```vue title="src/components/PedidoTabla.vue"
<script setup lang="ts">
import type { Pedido } from '../types/pedido';

defineProps<{ pedidos: Pedido[]; cargando: boolean }>();
defineEmits<{
  (e: 'editar', pedido: Pedido): void;
  (e: 'eliminar', id: number): void;
}>();

const formatearMoneda = (val: number) =>
  new Intl.NumberFormat('es-MX', { style: 'currency', currency: 'MXN' }).format(val);

const formatearFecha = (fechaStr: string) =>
  new Date(fechaStr).toLocaleString('es-MX', { dateStyle: 'medium', timeStyle: 'short' });
</script>

<template>
  <div v-if="cargando">Cargando pedidos...</div>
  <div v-else-if="pedidos.length === 0">No hay pedidos registrados.</div>
  <table v-else>
    <tr v-for="ped in pedidos" :key="ped.id!">
      <td>#{{ ped.id }}</td>
      <td>{{ formatearFecha(ped.fecha) }}</td>
      <td>{{ ped.cliente.nombre }} — {{ ped.cliente.email }}</td>
      <td>{{ formatearMoneda(ped.total) }}</td>
      <td>
        <button @click="$emit('editar', ped)">Editar</button>
        <button @click="$emit('eliminar', ped.id!)">Eliminar</button>
      </td>
    </tr>
  </table>
</template>
```

:::note[💡 Concepto: `Intl`, el formateador nativo del navegador]
`Intl.NumberFormat` e `Intl.DateTimeFormat` (usado aquí vía `toLocaleString`) son APIs nativas
de JavaScript para formatear números, monedas y fechas respetando las convenciones de una
configuración regional (*locale*) — en este caso `es-MX`. No necesitas ninguna librería externa
para mostrar `$150.50` en vez de `150.5`, o `7 sep 2026` en vez de `2026-09-07T13:36:00`.
:::

## 3.7 El componente raíz: App.vue

Es el único componente que habla con `pedidoService` directamente, y el que mantiene el estado
compartido: la lista de pedidos, si está cargando, y cuál pedido (si alguno) se está editando.

```vue title="src/App.vue"
<script setup lang="ts">
import { ref, onMounted } from 'vue';
import { pedidoService } from './services/pedidoService';

const pedidos = ref<Pedido[]>([]);
const cargando = ref(false);
const pedidoSeleccionado = ref<Pedido | null>(null);

const cargarPedidos = async () => {
  cargando.value = true;
  pedidos.value = await pedidoService.obtenerTodos();
  cargando.value = false;
};

const guardarPedido = async (pedidoData: Pedido) => {
  if (pedidoData.id) {
    await pedidoService.actualizar(pedidoData.id, pedidoData);
  } else {
    await pedidoService.crear(pedidoData);
  }
  pedidoSeleccionado.value = null;
  await cargarPedidos();
};

const borrarPedido = async (id: number) => {
  if (confirm(`¿Eliminar el pedido #${id}?`)) {
    await pedidoService.eliminar(id);
    await cargarPedidos();
  }
};

onMounted(cargarPedidos); // se ejecuta una vez, cuando el componente aparece en pantalla
</script>

<template>
  <PedidoForm :pedidoAEditar="pedidoSeleccionado" @guardar="guardarPedido" @cancelar="pedidoSeleccionado = null" />
  <PedidoTabla :pedidos="pedidos" :cargando="cargando" @editar="(ped) => pedidoSeleccionado = ped" @eliminar="borrarPedido" />
</template>
```

Fíjate en la decisión clave de `guardarPedido`: **si el pedido tiene `id`, es un PUT
(actualizar); si no lo tiene, es un POST (crear)**. Con esa única condición, un mismo
formulario sirve para ambas operaciones.
