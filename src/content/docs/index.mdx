## ¿Qué vas a construir?

Un sistema de **Pedidos**: cada pedido tiene una fecha, un total en dinero, y un cliente (con
nombre y email). Vas a poder **crear**, **ver**, **editar** y **eliminar** pedidos desde una
interfaz web que habla con una API por HTTP. Es el ejercicio clásico de CRUD (Create, Read,
Update, Delete), con dos detalles que lo hacen más realista que un ejemplo de "tareas
pendientes":

- Cada pedido tiene un **objeto anidado** (el cliente dentro del pedido), no solo campos sueltos.
- Maneja **fechas** y **números decimales** (dinero), dos fuentes clásicas de bugs para quien empieza.

:::note[💡 Concepto: ¿qué es un CRUD?]
CRUD es un acrónimo de las cuatro operaciones básicas que casi cualquier aplicación hace sobre
datos: **C**rear, **R**ead (leer), **U**pdate (actualizar) y **D**elete (eliminar). Casi todo
software con una base de datos — una red social, una tienda, un banco — es, en el fondo,
muchos CRUDs conectados entre sí. Dominar cómo construir uno de punta a punta (interfaz → API
→ almacenamiento) es una de las habilidades más transferibles que existen en programación.
:::

## Arquitectura del proyecto

Vas a construir dos piezas, empezando de una carpeta completamente vacía:

- **Backend.Api** — una API REST en .NET que expone `/api/pedidos`. La construyes desde cero en la [Parte 1](/guia/parte-1-backend/).
- **Frontend.UI** (Vue) o **Frontend.Angular** — la interfaz que consume esa API. La construyes desde cero, con el framework que elijas, en la [Parte 3](/guia/parte-3-vue/).

Nada de este proyecto existe todavía en tu máquina — cada comando `dotnet new`, `npm create` o
`ng new` que vas a correr en esta guía crea algo nuevo. Al final de la Parte 1 y la Parte 3
vas a tener carpetas reales, con código que tú escribiste, corriendo en tu computadora.

```text title="arquitectura"
┌────────────────────┐        HTTP / JSON        ┌──────────────────────┐
│  Frontend.UI (Vue)  │ ────────────────────────▶ │                      │
│  ó Frontend.Angular │ ◀──────────────────────── │     Backend.Api      │
└────────────────────┘   GET / POST / PUT / DELETE│      (.NET / C#)     │
                                                    └──────────┬───────────┘
                                                               │
                                          Strategy intercambiable
                                                               │
                                 ┌─────────────┬────────────────┴──────────────┐
                                 ▼             ▼                               ▼
                         pedidos.json   pedidos.xml                  pedidos.db (SQLite)
                          (por defecto)                             (Parte 5, opcional)
```

El punto clave que vas a ver una y otra vez en esta guía: **el frontend nunca sabe cómo se
guardan los datos**. Solo habla HTTP con la API. Eso es lo que te permite, más adelante,
cambiar de archivos JSON a una base de datos SQLite sin tocar ni una línea del frontend.

## Requisitos previos

Esta guía asume que ya sabes HTML/CSS básico y JavaScript/TypeScript básico (variables,
funciones, `async/await`). No necesitas experiencia previa con Vue, Angular, .NET ni bases de
datos: eso es justamente lo que enseña esta guía.

## Herramientas que necesitas instalar

:::

## Cómo está organizada esta guía

Después de entender el backend (Parte 1), vas a **elegir un camino** en la Parte 2: construir
el frontend con **Vue** o con **Angular**. No hace falta que hagas los dos — elige el que
quieras aprender primero. Ambos caminos terminan en el mismo lugar: la Parte 4 (conectar todo)
y la Parte 5 (SQLite), que aplican sin importar qué frontend hayas elegido.
